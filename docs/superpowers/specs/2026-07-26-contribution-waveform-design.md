# GitHub Contribution Waveform — Design

Date: 2026-07-26
Status: approved pending review
Owner: olivierluethy

## 1. What this is

A build tool that renders a GitHub user's contribution history as a continuous
waveform (line chart over time) instead of the classic square heatmap, emits
self-contained SVG files, publishes them on GitHub Pages, and provides a
copy-paste `<picture>` snippet for a profile README.

Fixed decisions:

| Decision | Value |
|---|---|
| GitHub username | `olivierluethy` |
| Repository name | `contribution-waveform` |
| Pages base URL | `https://olivierluethy.github.io/contribution-waveform/` |
| Accent color | `#7c3aed` |
| Mirrored waveform | **on** by default |
| Animation | one-shot draw-in, CSS inside the SVG |
| All-years layout | height grows with year count |

## 2. Platform constraints that drive the architecture

These are given, not derived, and the design must not violate them:

1. GitHub Pages is static hosting. No server code, no per-request generation.
   Everything embeddable is a file committed/deployed ahead of time.
2. GitHub sanitizes README HTML. `<script>`, `<iframe>`, `<canvas>`, `<style>`
   blocks and event handlers are stripped. Only images render reliably.
3. The embed is therefore an SVG file over HTTPS, regenerated by a scheduled
   GitHub Action.
4. Animation must live inside the SVG (CSS `@keyframes` in an inline `<style>`,
   or SMIL). Never external JS.
5. The SVG must be fully self-contained: no `<script>`, no `<foreignObject>`,
   no external fonts, no external image refs, no `http://`. Font stack is
   `ui-sans-serif, -apple-system, "Segoe UI", sans-serif` only.
6. GitHub proxies images through camo and caches them for hours. Daily updates
   are the expected cadence. We do not attempt to defeat the cache.

**Consequence — arbitrary usernames are out of scope.** A static site cannot
generate a graph for a visitor's username on demand. The repo is configured for
exactly one username; others fork and set their own. A serverless variant is
noted in the README as possible future work and is *not* implemented.

## 3. Architecture

A pure pipeline. Each stage has one job and a plain-data interface, so the math
is testable without touching SVG and the rendering is testable without network.

```
fetch.ts     GraphQL v4, year-by-year  ──▶ data/contributions.json
                                            (raw, date-sorted, pretty)
                                                    │
transform.ts  windowing, rolling 7/30,              ▼
              p98 clamp, normalize        ──▶ PlotSeries (plain numbers)
                                                    │
curve.ts      Catmull-Rom → cubic Bézier  ──▶ path `d` strings
                                                    │
render.ts     SVG string composition      ──▶ dist/*.svg
themes.ts     color tokens                    (6 files)
config.ts     zod-validated config
cli.ts        build / fetch / flags
```

`transform.ts` and `curve.ts` are pure functions over arrays and know nothing
about SVG. `render.ts` does placement and string assembly, not statistics.

### File layout

```
.
├── src/
│   ├── config.ts      # zod schema, loads waveform.config.json
│   ├── fetch.ts       # GraphQL client + year-by-year pagination

│   ├── curve.ts       # Catmull-Rom → cubic Bézier path builder

│   └── cli.ts         # entrypoint
├── site/              # Vite + Tailwind GitHub Pages site (dark only)
├── test/fixtures/     # contributions.sample.json + snapshots
├── data/contributions.json
├── dist/              # generated SVGs (committed, deployed)
├── waveform.config.json
└── .github/workflows/build.yml
```

### Toolchain

Runtime dependencies stay within the stated budget: `graphql-request`, `zod`.
Test runner: `vitest`. No charting library — SVG is emitted as strings and the
curve math is hand-rolled.

Dev dependencies beyond that are required by the stated stack and are additions
to the dev toolchain, not the runtime dep list:

- `typescript` + `@types/node` — the CLI is TypeScript and the Action pins
  Node 20, which cannot strip types natively. `tsc` compiles `src/` to `build/`
  and the CLI runs as `node build/cli.js`.
- `vite`, `tailwindcss`, `@tailwindcss/vite` — required by §6 for the site.

Single root `package.json`, ESM (`"type": "module"`).

Scripts: `fetch`, `build`, `build:site`, `test`, `typecheck`.

## 4. Data acquisition

GraphQL API v4:

```graphql
query($login: String!, $from: DateTime!, $to: DateTime!) {
  user(login: $login) {
    createdAt
    contributionsCollection(from: $from, to: $to) {
      contributionCalendar {
        totalContributions
        weeks { contributionDays { date contributionCount } }
      }
    }
  }
}
```

- `contributionsCollection` accepts at most a one-year window, so the fetcher
  loops year by year from the account's first year to today.
- First year comes from `user { createdAt }`.
- Auth from `process.env.GITHUB_TOKEN`. The Action prefers the repo secret
  `GH_PAT` (classic PAT with `read:user`) and falls back to the default
  `GITHUB_TOKEN`.
- Result cached to `data/contributions.json`: pretty-printed, days sorted by
  date, duplicates across year boundaries de-duplicated by date.
- `--offline` builds entirely from that file, no network.

Private contributions only appear when the PAT has `read:user` **and** "Include
private contributions on my profile" is enabled in GitHub settings. Documented
in the README.

### Timezone

The API returns dates already bucketed by GitHub. `timezone` in config
(`Europe/Zurich`) is used only to determine what "today" is when computing the
trailing 365-day and 31-day windows, so a build running at 04:00 UTC picks the
correct local end date.

## 5. Transform

Input: full date-sorted series. Output: a `PlotSeries` of plain numbers.

**Rolling averages.** Trailing windows of 7 and 30 days. Where history exists
*before* the visible window, it is used to seed the rolling average, so the
left edge of a trailing-365 chart does not show a ramp-up artifact. Where it
does not exist (start of account history), the window is partial: the mean of
the days available so far.

**Percentile clamp.** Y scale is the 98th percentile of the daily values in the
window, nearest-rank: sort ascending, take index `clamp(ceil(0.98 * n) - 1, 0,
n - 1)`. Values above it are clipped to it. Zeros are included in the
distribution. Guards: if p98 is 0, fall back to the window max; if the max is
also 0, use 1. This is what prevents a single 200-commit day from flattening
the rest of the wave, and what prevents division by zero producing `NaN` in a
path `d` attribute.

**Normalization.** Values map to `[0, 1]` and then to plot coordinates. X is
uniform: `x_i = plotLeft + i * plotWidth / (n - 1)`. A single-point series
(`n === 1`) degenerates to a flat horizontal line rather than dividing by zero.

**Peak markers.** Top N days by count within the window, N from config
(default 3), with a minimum separation of 7 days between selected peaks so
three markers do not stack on one spike. Label is the raw count, drawn above
the dot and clamped inside the viewBox.

## 6. Curve

Uniform Catmull-Rom converted to cubic Bézier, tension `t = 0.5`. For points
`p0, p1, p2, p3` the segment `p1 → p2` uses:

```
cp1 = p1 + (p2 - p0) * t / 3
cp2 = p2 - (p3 - p1) * t / 3
```

At `t = 0.5` this is the classic `/6` form. Endpoints duplicate the terminal
point (`p0 = p1` for the first segment, `p3 = p2` for the last). Coordinates
are rounded to 2 decimals to keep file size down. A fixture test pins the exact
output string.

## 7. Render

### Layer order, back to front

1. **Baseline band** — rolling 30-day average as a soft filled band.
2. **Deviation fill** — area between the daily curve and the 30-day baseline,
   accent where above average, muted where below.
3. **Rolling 7-day average** — thin smoothed line.
4. **Daily series** — smoothed Catmull-Rom curve. The wave.
5. **Peak markers** — dots with count labels on the top N days.

The deviation fill paints *before* the 7-day and daily strokes, not after.
Its top edge is the daily curve itself, so painting it on top would lay a
55%-opacity accent across the wave's own stroke and mute the outline —
fill-behind-stroke is the conventional and more legible choice.

### Deviation fill technique

Splitting the band analytically at every curve crossing is error-prone. Instead
the same closed band path (daily curve forward, baseline curve backward) is
drawn twice, each time under a different `clipPath`:

- `clip-above` = the baseline curve closed to the top of the plot → accent fill
- `clip-below` = the baseline curve closed to the bottom of the plot → muted fill

Exact, no crossing math, pure SVG.

### Mirror mode (default on)

The baseline envelope is mirrored along with the daily curve. Given center axis
`yc` and amplitude `a(t)`, the upper curve is `yc - a` and the lower is
`yc + a`; the same holds for the baseline envelope. The deviation fill is the
region between the mirrored daily envelope and the mirrored baseline envelope,
split above/below by the same clip technique applied to each half.

This is what preserves layer 4's meaning under mirroring: accent still means
"this day beat its 30-day average". Both halves are emitted as explicit paths
rather than a `<use>` reflection, to avoid renderer quirks.

`mirror: true` in config; `--mirror` / `--no-mirror` override on the CLI.

### Axes and chrome

- **X axis:** month tick marks with three-letter labels, positioned at the
  first day of each month, matching GitHub's calendar month layout. A label is
  skipped if it would land within 40px of the previous one.
- **Y axis:** no gridlines, no numbers. One subtle max-value label in the
  corner.
- **Footer:** `@olivierluethy · <total> contributions · <from> – <to>`.

### Geometry

| View | viewBox | Notes |
|---|---|---|
| year | `0 0 880 220` | plot inset: left 44, right 20, top 26, bottom 50 |
| month | `0 0 880 160` | plot inset: left 44, right 20, top 24, bottom 42 |
| all | `0 0 880 <44n + 60>` | one 44px row per year, 52px left gutter for year labels |

No `width`/`height` on the root `<svg>`; `preserveAspectRatio="xMidYMid meet"`.

The all-years height is a deliberate, approved deviation from the flat
`880 220` in the original brief — at eight or more years a fixed 220 compresses
each wave to roughly 20px, which is not legible. Year and month keep their
specced sizes exactly.

### Animation

CSS `@keyframes` in an inline `<style>` element inside each SVG. One shot, no
loop:

- Daily curve strokes itself left-to-right over ~1.4s. `pathLength="1000"` is
  set on the path so the dash math needs no measurement; `stroke-dasharray:
  1000` with `stroke-dashoffset` animating `1000 → 0`.
- Fills and markers fade in over 0.6s with a 0.6s delay.

**Graceful degradation is mandatory:** the element's *base* style is the
finished state (`stroke-dashoffset: 0`, `opacity: 1`) and the animation only
overrides it via the `from` keyframe. A renderer that ignores CSS animation
shows the completed image, never a blank one.

`@media (prefers-reduced-motion: reduce)` disables all animation.

### Outputs

| File | Content |
|---|---|
| `wave-year-dark.svg` | trailing 365 days, dark |
| `wave-year-light.svg` | trailing 365 days, light |
| `wave-month-dark.svg` | trailing 31 days, dark |
| `wave-month-light.svg` | trailing 31 days, light |
| `wave-all-dark.svg` | all years stacked, dark |
| `wave-all-light.svg` | all years stacked, light |

Both themes ship because the README is public and readers use both GitHub
themes; the embed uses `<picture>` with `prefers-color-scheme`.

### Themes

Solid hex plus `fill-opacity` (not `rgba()`) for maximum renderer
compatibility. Dark tokens track GitHub's dark surface (`#0d1117` background
family); light tokens track GitHub's light surface. Accent is `#7c3aed` in
both.

## 8. Config

`waveform.config.json`:

```json
{
  "username": "olivierluethy",
  "timezone": "Europe/Zurich",
  "peakMarkers": 3,
  "mirror": true,
  "accent": "#7c3aed"
}
```

zod schema: `username` matches GitHub's username rules; `timezone` validated by
constructing an `Intl.DateTimeFormat` with it; `peakMarkers` integer 0–10;
`mirror` boolean; `accent` a `#rrggbb` hex string.

## 9. Pages site (`site/`)

Vite + Tailwind, `base: '/contribution-waveform/'`, dark mode only, Tailwind
exclusively with no custom CSS beyond the Tailwind entry file. JavaScript is
allowed here — the sanitization limit applies only to the README.

Single page with:

1. Live previews of all six SVGs — year, month, all-years — with a theme toggle
   switching which theme variant of each is shown.
2. A snippet generator: one read-only code block per variant with a copy
   button, pre-filled with the real deployed URLs and username.
3. A "use this for your own account" section: fork → set `username` in
   `waveform.config.json` → add `GH_PAT` secret → enable Pages → done.
4. Modals (native `<dialog>`), not page redirects, for secondary content such
   as the "how it works" explainer.

**Deploy composition:** the Pages artifact is the Vite build output with
`dist/*.svg` copied to its root, so the embed URL is exactly
`https://olivierluethy.github.io/contribution-waveform/wave-year-dark.svg` and
the site itself is at the base path.

Generated snippet, exactly:

```html
<picture>
  <source media="(prefers-color-scheme: dark)"
          srcset="https://olivierluethy.github.io/contribution-waveform/wave-year-dark.svg">
  <source media="(prefers-color-scheme: light)"
          srcset="https://olivierluethy.github.io/contribution-waveform/wave-year-light.svg">
  <img alt="My GitHub contributions as a waveform"
       src="https://olivierluethy.github.io/contribution-waveform/wave-year-dark.svg">
</picture>
```

Plus a plain-Markdown fallback variant.

## 10. GitHub Action

`.github/workflows/build.yml`:

- Triggers: `schedule` (cron `0 4 * * *`), `workflow_dispatch`, `push` to
  `main`.
- Steps: checkout → setup-node 20 → `npm ci` → `npm run fetch` → `npm run
  build` → build site → compose artifact → `actions/deploy-pages`.
- Commits refreshed `data/contributions.json` and `dist/*.svg` back to `main`
  **only when content actually changed** (`git diff --quiet` check first), so
  no empty daily commits pollute the contribution graph the tool is drawing.
- Concurrency group so overlapping runs cancel.
- `permissions: contents: write, pages: write, id-token: write`.

Guard against recursion: the push-triggered run must not loop on its own
commit. The commit message carries `[skip ci]`, and the push trigger ignores
paths that only the bot writes.

## 11. Testing

Vitest, plus manual visual verification.

1. **Unit — transform:** rolling 7/30 math including partial windows and
   seeded-from-prior-history windows; percentile clamp including the p98 = 0
   and max = 0 fallbacks; normalization bounds.
2. **Unit — curve:** Catmull-Rom → Bézier output compared against a known
   fixture string; endpoint duplication; single-point and two-point series.
3. **Edge cases:** a user with zero contributions must not crash and must not
   emit `NaN`, `Infinity`, or `undefined` anywhere in a path `d` attribute.
   Sparse data (long zero runs) likewise.
4. **Sanitizer test:** parse each generated SVG and fail on `<script`,
   `<foreignObject`, `xlink:href` to an external origin, `@import`, or any
   `http://` reference.
5. **Snapshot test:** full SVG string built from
   `test/fixtures/contributions.sample.json`, so rendering changes show up in
   diffs.
6. **Offline build:** `npm run build -- --offline` succeeds with no network.
7. **Manual:** open each SVG in a browser; confirm the wave is legible at
   880px and at 400px wide.
